## 1. قياس أساس PageSpeed Insights (المصدر الخارجي: بنية Google)

**الأداة:** واجهة pagespeed.web.dev — نفس محرّك PSI (Lighthouse 13.5.0 على HeadlessChromium 153.0.8010.36) بمنظور خارجي من خوادم Google. **البيئة المختبرية للموبايل:** Moto G Power محاكًى + Slow 4G (نفس منهجية القياس المختبري المعتمدة بالتقرير القديم PERF-AUDIT-296، ما يجعل الأرقام قابلة للمقارنة عبر الزمن).

**حادثة الحصة (موثقة بأمانة):** النداء المباشر لواجهة PSI API رُفض بحصة 429 («Quota exceeded … pagespeedonline.googleapis.com» — نفس مانع التقرير الأصلي)، ومحاولة واجهة الويب الأولى اصطدمت بـ429 أيضًا. نجح المسار بإعادة المحاولة عبر الواجهة (reload) لكل تقرير. سجل القياس الخام محفوظ خارج الريبو (psi_baseline_results.json بجلسة القياس).

## 4. ما يظل مفتوحًا بعد هذا الإطار (حسب ترتيب التقرير — لا تنفيذ هنا)

- **P0-4 (التالي في الترتيب):** بدء قنوات الروابط بالمسار السريع — أدلة الأدوات المجانية الثمانية (AlternativeTo · SaaSHub · Product Hunt) ثم HARO. خارجي التنفيذ بالكامل (حسابات مالك)، وداخلية التحضير ممكنة بإطار مستقبلي بأمر صريح (حزمة إدراج جاهزة لكل أداة).
- **أداة تتبع الترتيب للاستعلامات الثلاثة:** قرار مالك (اختيار/اشتراك أداة) — لقطة SERP أعلاه هي البديل المتاح اليوم.
- **مفتاح PSI API (اختياري):** يرفع حصة 429 المتكررة للنداءات المباشرة؛ بدونه تبقى واجهة الويب (التي نجحت هنا) هي القناة.
- **متبقيات P0-3 نفسها:** بيانات حقل CrUX تنشأ تلقائيًا عند بلوغ عتبة الحركة؛ لوحة CWV بGSC بعد نافذة إعادة التدقيق.

## 5. حدود النطاق (إفادة إغلاق)

- **صفر مساس** بأي كود أو API أو قاعدة بيانات أو مصادقة أو دفع أو إعدادات Vercel/Cloudflare/GitHub أو أي ملف `src/` — إطار توثيق وقياس فقط (docs-only).
- **صفر إعادة تنفيذ** لما أُنجز: تحقق حي قبل القياس أن مسارات P0-1/P0-2 الستة على الإنتاج كلها `200` وموثوقة بالفريم 309.
- الأرقام أعلاه كلها مقيسة لحظة الالتقاط المذكورة، والمصدر خارجي (بنية Google / بحث حي) — لا رقم اجتهادي واحد في الجداول.
