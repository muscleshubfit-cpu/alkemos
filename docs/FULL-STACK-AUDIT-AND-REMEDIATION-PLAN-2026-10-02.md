## 1. الملخص التنفيذي

المستودع **ناضج منضبط بشكل استثنائي** بمقاييس حجمه: كل بوابات الجودة خضراء عند شجرة الفحص (tsc صفر أخطاء · eslint صفر أخطاء وتحذير موثق واحد · vitest ‏2,074/2,074 · build ‏2,033/2,033 صفحة)، مصادقة API موحّدة عبر `getUser()` بلا استثناء، حماية RLS على كل جدول، ومال/محافظ محمية بـ RPCs ذرية وحسابات idempotent في مسارات الأموال الحرجة. التدقيق لم يجد أي عطل «كاسر» حيًّا في المسارات الرئيسية.

المخاطر الحقيقية المتبقية تتركز في **4 عناقيد**:

1. **أمان التبعيات المقفلة**: `bun.lock` يثبّت `next@16.3.2` — ضمن نطاق 3 استشارات حرجة (RCE) صدر إصلاحها في 16.3.3؛ أحد مساراتها (`next/og` ImageResponse) **عام فعليًا** عبر `/api/og-image/[slug]`، ومسار الصور مُخفَّض الخطورة بالتصميم (`unoptimized: true` + 410 على `/_next/image`) لكن المسار الثالث (خوادم ويندوز) لا ينطبق على Vercel. التحديث متاح محليًا بـ `bun update next` (16.3.8) — إصلاح رخيص عالي القيمة.
2. **تكامل الأموال في PayPal**: إعادة إرسال `POST /api/paypal/capture-order` لأمرٍ مُحصَّل بالفعل تعيد تمديد الاشتراك **مجانًا في كل مرة** (ذراع الاشتراك بلا حماية تكرار، بينما ذراع شحن المحفظة محميّة بمسجل UUID5 — عدم تناسق مؤكد بالكود).
3. **SEO**: `robots.txt` تحجب عنكبوتات جوجل من صفحات `/authors` العامة (صفحات E-E-A-T التي تعلن عنها الخريطة نفسها!) + 3 عيوب JSON-LD مؤكدة في كل صفحات `/compare` الثمانية (روابط مزدوجة البادئة · تواريخ مفبركة بوقت العرض · `mainEntityOfPage` يشير لمسارات غير موجودة).
4. **إمكانية الوصول للأوفرلايات**: درج EVO (على كل صفحة) ودرج الموبايل و3 نوافذ مشروطة يدويًا بلا دلالات حوار ولا فخ تركيز ولا Escape — مع زر إغلاق واحد يُصيَّر **فارغًا حرفيًا**.

## 4. النتائج التفصيلية

### 4.1 الأمن والموثوقية (S)

**S-01 · Security/Reliability · عالية · [مُتحقَّق مباشرة] — إعادة تشغيل التقاط PayPal تمدد الاشتراك مجانًا (لا idempotency بذراع الاشتراك)**
- الموقع: `src/app/api/paypal/capture-order/route.ts:529-543` (ذراع الاشتراك — بلا فحص تكرار) مقابل `:263-281` (ذراع المحفظة — محميّ بفحص `ref_id` قبل الإضافة) · `src/lib/paypal.ts:385-395` (422 `ORDER_ALREADY_CAPTURED` ← يُعامَل نجاحًا ويجلب تفاصيل الأمر)
- الدليل: الذراعان في نفس الملف — المحفظة تفحص `coach_wallet_transactions.ref_id` (UUID5 حتمي من الـorderId) قبل الإضافة؛ ذراع الاشتراك تستدعي `serverUpsertSubscription(user_id, canonicalTier, duration_months)` مباشرة. إعادة إرسال الطلب على أمر مُحصَّل ← 422 ← «نجاح» ← تمديد آخر `duration_months` **في كل إعادة**. (لاحظ أن `PayPal-Request-Id: mhe-capture-${orderId}` يحمي الزبون من الخصم المزدوج — العيب في الأثر جانب الموقع فقط.)
- الأثر: دفعة واحدة = شهور غير محدودة لمن يعيد الإرسال (أو حتى إعادة محاولة عرضية من المتصفح بعد نجاح صامت).
- اتجاه الإصلاح: مسجل idempotency على مستوى الـorderId لذراع الاشتراك (نفس نمط `payPalOrderRefUuid` — سطر موجود بجدول `subscription_requests`/مسجل مخصص بفهرس فريد، أو تمرير مرجع الأمر إلى `extend_subscription` مع فحص داخل RPC). **منطقة §7 — تتطلب موافقة المالك المسبقة قبل التنفيذ.**

**S-02 · Security/Reliability · عالية — التبعية المقفلة `next@16.3.2` داخل نطاق 3 استشارات RCE حرجة**
- الموقع: `bun.lock` (القفل `"next@16.3.2"`) مقابل `package.json:34` (`"next": "^16.1.1"`) · المسار العام المتأثر: `src/app/api/og-image/[slug]/route.tsx:1` (`import { ImageResponse } from "next/og"`)
- الدليل: `bun audit` عند شجرة الفحص: 3 critical لـ`next >=16.0.0 <16.3.3`:
  - GHSA-p293-qw3h-jr36 (RCE غير مصادق — خوادم ويندوز): **غير منطبق** على Vercel (لينكس) لكنه خطر تطوير محلي على ويندوز.
  - GHSA-2xp9-vwfh-vxw4 (RCE في Image Optimization API مع AVIF): **مُخفَّض بالتصميم** — `images.unoptimized: true` (`next.config.ts:40`) + `middleware.ts:79-81` يرجع 410 لأي `/_next/image` قبل عمل المُحسِّن. يبقى التحديث مطلوبًا كدفاع بالعمق.
  - GHSA-vcvr-r3jv-pc5j (RCE في `next/og` ImageResponse): **المسار موجود وعمومي** — مولّد بطاقات OG العام يستورد `ImageResponse` ويخدمه بلا مصادقة (مستثنى من middleware لأسباب كاش).
- الأثر: سطح هجوم حرج على نسخة الإنتاج؛ حتى مع تخفيف مسار الصور، مسار `next/og` حي.
- اتجاه الإصلاح: `bun update next` (يقفز إلى 16.3.8 داخل النطاق الدلالي) + `sharp` (0.35.3 → ≥0.35.4) ثم البطارية الكاملة ونشر فعلي (فريم كود — **ليس** `[vercel skip]`).

## 5. ما تم التحقق من سلامته (إيجابيات موثقة بالكود)

هذه ليست مجاملة — نتائج فحص فعلي بالدليل، تُدرج لتوثيق الحدود الآمنة التي لا تحتاج عملًا:

- **المصادقة**: صفر استخدام لـ`getSession()` بكود API (المصدر الوحيد عميل تجريبي محلي) — كل الخادم عبر `getUser()` + تحميل الدور؛ كل مسارات `/admin/*` (100%) تتحقق من الدور خادميًا؛ فحوص IDOR/ملكية حيث يجب (plans · ai/jobs · support · coach-whatsapp · activate).
- **أسرار CRON**: كل مسارات cron الثمانية + dispatch-pipelines + evo/followup تستخدم `verifyCronAuth` (timing-safe، fail-closed) — استثناء واحد موثق (S-10).
- **PayPal webhook**: تحقق توقيع عبر واجهة PayPal الرسمية؛ لا يكتب أموالًا أبدًا (log-only)؛ عكس الاسترداد idempotent.
- **اقتصاديات المحفظة**: خصم-first عبر `coach_adjust_wallet` RPC (صف-مقفل، لا سالب) + استرداد عند فشل التفعيل + عمولات idempotent على paymentId + شحن المحفظة محمي تكرار UUID5 — ذراع الاشتراك هو الاستثناء الوحيد (S-01).
- **الرفع والملفات**: قوائم MIME سماح + شم البايتات السحرية + سقف 5MB + مسارات يعيد بناءها الخادم + سقوف لكل مستخدم؛ `/api/file` يرفض `..` ويجيز مالك-البادئة أو طاقمًا فقط.
- **RLS**: كل CREATE TABLE يتبعه ENABLE ROW LEVEL SECURITY (61 عبارة/41 ملفًا — بما فيها استرجاع 0056/0088 الحرفي بعد حادثة المرحلة 61)؛ كل دوال SECURITY DEFINER (30+) تثبّت `search_path`؛ السجلات الحساسة RLS-on بلا سياسات عميل.
- **طبقة AI**: توقيتات AbortController لكل محاولة مع تنظيف finally، عقد إحباط منتصف البث، تدوير مفاتيح، clamp بمدخل لكل Groq مع راجع env — صلابة مبنية على حوادث مقيسة.
- **الأداء البنيوي (موثق وسليم)**: بيانات 8,830/868 لا تصل حزمة العميل إطلاقًا (جزر خادمية) · recharts/PayPal/Supabase كسولة · prefers-reduced-motion تغطية فعلية شاملة (تحقق بالمصدر) · خطوط metric-adjusted مع fallbacks · دخول أطراف ثالثة خلف موافقة/خمول.
- **SEO (سليم)**: canonical على كل سطح عام (98 ملفًا) · hreflang متبادل 100% مع x-default على 86 سطحًا (مثبت باختبارات) · لا soft-404 (كل قالب ديناميكي يستدعي notFound) · صفر عناوين مكررة عبر 8,830 صفحة صنف · أوصاف ≤160 بقانون كاناري · خرائط كاملة مع lastmod عائلي صادق · أسطح خاصة noindex.
- **الاختبارات**: 123 ملفًا/2,074 حالة تعمل نظيفة — من أقوى ما في المستودع: كاناريات تثبّت قوانين التحرير/MSA/الروابط/الOG بجذر الكود.
