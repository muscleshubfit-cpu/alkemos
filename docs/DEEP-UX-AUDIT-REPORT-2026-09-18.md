## 1. الملخص التنفيذي

اختُبرت المنصة ك مستخدم حقيقي عبر المصفوفة الكاملة: **Guest / Free / Premium (عبر تفعيل مدرب) / Pro / Coaching / B2C Coach / Mobile UX / عزل الأدوار والجلسات**. البوابات الأمنية على مستوى الـ API كلها سليمة (401/403 في مواضعها — لا استغلال واحد مؤكد خارج C1). النتيجة الحاسمة:

1. **C1 (حرج):** تسريب RLS فعلي في `admin_notifications` — حساب مدرب B2B عادي قرأ **34 إشعارًا موجهة لغيره** (عملاء جدد بإيميلاتهم، مدربون جدد، طلبات دفع)، وظاهرة في واجهة جرس الإشعارات. السياسة الحية في قاعدة البيانات أوسع من المعرّفة في migrations المستودع (Drift).
2. **H1:** فشل Hydration ‏#418 في React على **كل الصفحات العامة للزوار المجهولين** (بروفايل نظيف) — الصفحات للمسجّلين سليمة.
3. **M1–M2:** رسائل خطأ الخادم بلغة واحدة داخل واجهة اللغة الأخرى (أوقات الدفع/الدخول الحاسمة) + تسجيل بإيميل موجود ينتهي لطريق مسدود مُضلِّل.
4. **m1–m9:** تسع ثغرات UX/نظافة كود صغيرة (أهداف لمس موسوعة، تسريب محادثة EVO على الجهاز، تناقض عدد الأدوات، Enum خام… إلخ) — بلا خطر مباشر.

**التسلسل الموصى به للإصلاح:** C1 ← H1 ← M2 ← M1 ← دفعة MINOR ← قرارات المنتج (انظر §7).

**قرار صريح من المالك مطلوب قبل أي تنفيذ** لخمسة بنود (§6) — أبرزها: تفعيل تأكيد البريد (يحدد شكل إصلاح M2).

## 3. النتائج (Findings) مرتبة بالخطورة

> «سبب مؤكد» = مُتحقق من الكود المصدر مباشرةً بالجلسة. «غير مؤكد» = نتيجة Black-box تحتاج تشخيصًا أعمق قبل الإصلاح.

### 🔴 C1 — تسريب RLS في `admin_notifications` (مدرب يقرأ إشعارات غيره)

- **المشكلة:** حساب مدرب B2B عادي (غير staff/admin) قرأ 34 صفًا من `admin_notifications` موجهة لمدربين آخرين/للإدارة: **عملاء جدد بإيميلاتهم الكاملة، مدربون جدد، طلبات دفع/شحن محفظة** — والبيانات ظاهرة فعليًا في واجهة جرس الإشعارات الخاصة بالمدرب.
- **التأثير الحقيقي:** أي مدرب مسجل يرى عملاء المنصة الجدد (إيميلات PII) لحظة انضمامهم — قناة مباشرة لسرقة عملاء بين المدربين المنافسين + رؤية حركة دفع الآخرين. أخطر بنود التقرير لأنه عبر-حسابات ومؤكد وقابل لإعادة الإنتاج فورًا.
- **السبب (مؤكد — انحراف بين المستودع والقاعدة الحية):** migration ‏`RUN_ON_SUPABASE_0030C_MULTI_COACH_ADMIN_RLS_NOTIFS.sql` (الأسطر 146–156) يعرّف السياسة المقيدة: `is_admin() or (is_staff() and (target_coach_id is null or target_coach_id = auth.uid()))` — أي أن المدرب العادي لا يرى إلا إشعاراته المستهدفة. السلوك الحي (قراءة صفوف targeted لغيره) يثبت أن **السياسة المطبقة على الـ DB الحية أوسع من ملفات المستودع** ( نفس النمط المذكور لميجريشن 0056). الإصلاح: إعادة تطبيق السياسة المقيدة على الحية ثم إعادة الفحص بحساب مدرب.
- **إعادة الإنتاج:** سجّل دخولًا بأي حساب مدرب ب2B → افتح صفحة المدرب → الجرس/جلب `/admin/notifications` المسار الذي يقرأ الجدول → تظهر إشعارات بـ `target_coach_id` ≠ معرف المدرب الحالي.

### 🟠 H1 — فشل Hydration ‏#418 على كل الصفحات العامة للزوار المجهولين

- **المشكلة:** خطأ React ‏#418 (server/client mismatch) يظهر على **جميع الصفحات العامة** لزائر ببروفايل نظيف/تخزين ممسوح (حالة الزائر الجديد من SEO تمامًا). صفحات المسجّلين نظيفة.
- **التأثير الحقيقي:** الشريحة الأهم (الزوار الجدد) تواجه أخطاء Console على أول زيارة، مع خطر كسر التفاعلية في عناصر الصفحة وأثر محتمل على CWV/الترتيب. يتناقض مع رصيد «صفر أخطاء كونسول» الموثق للمرحلة 224 (كان قياس دخان المسارات الأربعة فقط بعد الإصلاح — لا يعمم كل الصفحات العامة).
- **السبب (غير مؤكد — Black-box):** المرشح الأول: السكربتات المضمنة قبل الـ Hydration في `src/app/layout.tsx` (bootstrap موافقة الكوكيز عند السطر ~368 + gtag) أو توقيت CookieConsent — لكن لم يُثبت أيا منها نهائيًا. التشخيص المطلوب: إعادة الإنتاج بـ React dev build لقراءة الـ stack الكامل.
- **إعادة الإنتاج:** بروفايل متصفح جديد كليًا (أو مسح التخزين) → افتح أي صفحة عامة (EN أو AR) → Console: ‏#418.

### 🟡 M1 — رسائل خطأ الخادم بلغة واحدة داخل واجهة اللغة الأخرى

- **المشكلة:** (أ) تفعيل اشتراك بمحفظة غير كافية يرجع 402 برسالة عربية كاملة داخل الواجهة الإنجليزية. (ب) كلمة مرور خاطئة عند الدخول تعرض "Invalid login credentials" إنجليزية داخل الواجهة العربية.
- **التأثير الحقيقي:** في اللحظات الأعلى قيمة (دفع/تفعيل/دخول) نصف المستخدمين لا يفهمون الخطأ → توقف التحويل وتذاكر دعم كان يمكن تجنبها.
- **السبب (مؤكد):** نصوص الرسائل مكتوبة Hardcoded داخل مسارات الـ API — مثال مؤكد: `src/app/api/coach/subscriptions/activate/route.ts` (رسالة `insufficient_wallet` بالعربية، الأسطر ~250–282). لا يوجد تمرير لغة/معامل i18n لمسارات الأخطاء.

### 🟡 M2 — التسجيل بإيميل موجود = طريق مسدود مُضلِّل

- **المشكلة:** محاولة إنشاء حساب ببريد مسجل تعرض «افحص بريدك» — بينما **لا يوجد أي إرسال بريد أصلًا** (التسجيل فوري بلا تأكيد في الإنتاج) والمستخدم ينتظر رسالة لن تصل.
- **التأثير الحقيقي:** العائدون بالبريد المسجل (شريحة استرجاع طبيعية) يعلقون في حلقة موهومة → فقدان مستخدمين + تذاكر «لم يصل الإيميل».
- **السبب (مؤكد):** مسار التسجيل يرجع رسالة النجاح العامة لحالة البريد المكرر بدل «الحساب موجود — سجّل دخولك».

## 4. ما تم التحقق من نجاحه (سياق الفهم فقط — الباقي سليم)

- **بوابات الأدوار كلها صحيحة:** `/admin` يعيد توجيه الضيف→`/auth` والـ Free→`/dashboard` والمدرب→`/coach`؛ كل مسارات الـ API الإدارية 401/403 بحسب الدور؛ webhook+cron ‏401 بدون توكن. **→ C1 هو التسريب الوحيد** في السطح المختبر.
- **بوابة المحفظة سليمة سيرفريًا:** التفعيل بمحفظة فارغة رجع 402 `insufficient_wallet` مع أرضية الباقة $6/$16 مفروضة من الخادم (يخفض m7 ل hygiene).
- **الجلسات:** استمرارية عبر التحديث/إعادة الدخول/جهاز جديد + `/dashboard` بعد الخروج يعيد لـ`/auth`.
- **صفحة هبوط المدرب pending-review ترجع 404 عامة** (سلوك صحيح حتى الموافقة).
- **مسار الدعم يعمل E2E** (تذكرة أُنشئت 200 وظهرت بالقائمة).
- **حصص AI سيرفريًا** مع Toaster exhaustion صحيحة (EVO «6 messages left» · مخططات 0/2).
- **الموبايل:** صفر horizontal overflow على 12+ صفحة، RTL عربي صحيح، برغر 44px، تسجيل→dashboard كامل من الموبايل.

## 7. Recommended Fix Order

1. **C1** — إعادة تطبيق سياسة `admin_notifications` المقيدة (0030C) على الـ DB الحية + إعادة فحص بحساب مدرب (أولوية قصوى — خصوصية PII عبر-الحسابات).
