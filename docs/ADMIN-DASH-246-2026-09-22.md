## 1. تشخيص البنود الثلاثة — الجذور (مثبتة بالكود قبل الإصلاح)

### B1 — «عدد العملاء» في الداشبورد ≠ رقم جدول العملاء
- **الجذر:** داشبورد الأدمن كان يقرأ `get_coach_client_stats` (عدّاد بعدسة الكوتش: `role='client'` حصرًا)، بينما `/admin/clients` يقرأ `get_admin_clients_stats` (كل profiles: عملاء + مدربين + أدمن). مقياسان مختلفان تحت عائلة تسمية واحدة — والجدول كان الصحيح داخليًا (بلاطته = تبويب «الكل» = إجمالي الترقيم).
- **الإصلاح:** الداشبورد يستدعي **نفس RPC صفحة العملاء** — التطابق صار تعريفيًا لا تصادفيًا — وبلاطة واحدة صادقة «إجمالي الحسابات» بسطر تفصيل «منهم X عميل · Y مدرب» بدل «إجمالي العملاء» المضلل.

### B2 — زر «الإيصال» لا يعمل (ميت بفشلين متراكبين + فشل صامت)
1. **مسار مضاعف البادئة:** منذ إصلاح Phase 217 يخزّن `/api/upload` الكائن داخل bucket `receipts` بالمفتاح `<uid>/<file>` لكن يُرجع للـDB المسار المسبق `receipts/<uid>/<file>` (لقانون ملكية الشحن) — القارئ القديم كان يوقّع `receipts/receipts/…` = Not Found لكل الإيصالات الجديدة.
2. **لا سياسة SELECT على bucket receipts:** تحصين 0071 أسقط السياسة الشاملة ولم يُنشأ بديل — توقيع المتصفح ميت للجميع حتى بمسار صحيح.
3. **فشل صامت:** `{ data }` بلا قراءة error + `if (url)` بلا else — صفر توست، صفر لوج، الزر «لا شيء».
- **الإصلاح:** القراءة كلها عبر **البروكسي المفوّض سلفًا `GET /api/file`** (staff `role≠client` + service-role داخليًا — نفس المسار الذي يرجعه `/api/upload` وكان يُرمى): جديد `src/lib/receipt-view.ts` نقيّتان (`receiptObjectKey` تطبّع الشكلين الجديد والليجاسي + `receiptViewUrl`) — إحلال في AdminPaymentsView وAdminWalletsView وCoachWalletView + حذف `getReceiptSignedUrl` + فتح متزامن (popup blockers لا تأكل النقرة). شكل الكتابة في DB لم يُمس (قانون receipt-ownership سليم).

### B3 — «الإشعارات كلها تظهر للادمن» (+ مراجعة باقي الأدوار)
- **الجذر (طبقات):** الجرس الإداري يقرأ `admin_notifications` **بلا أي فلتر** وRLS (0088) يمنح الأدمن كل الصفوف (`is_admin()`) — بما فيها pings المدربين الخاصة (عملاء جدد/استبيانات/اعتمادات خطط لمدربين معيّنين). فوقها: 3 أنواع أعمال **إدارية** كانت تبث بـNULL لكل الطاقم (`coach_ad` · `coach_support` · `payout_request`)، وتذاكر الدعم بالمسار الخادمي كانت توجَّه إلى **معرّف العميل نفسه** (`target_coach_id: auth.id` — صف لا يراه أحد سوى الأدمن)، و«تعليم الكل مقروء» كان يكتب **كل** صفوف الجدول — فيمسح غير المقروء من جرس مدربين آخرين.
- **الإصلاح (بلا ميجريشن):** جديد `GET /api/notifications/admin` (service-role بفلتر `target_coach_id is null أو ∈ admin ids` — يضمن رؤية كل الأدمن لكل صف موجّه للأدمن أياً كان من اختار المستقبِل) + `listAdminNotificationsForAdmin` + الجرس واعٍ بالدور (الكوتش يبقى على RLS fetch: صفوفه + البث) + `markAdminNotificationsRead(ids)` بمعرفات الظاهر حصرًا + إعادة توجيه الأنواع الثلاثة إلى الأدمن **عند الإرسال** (فيتوقف تسربها للكوتشز فورًا) + توجيه التذاكر: المدرب المعيّن ← fallback الأدمن (مطابق للمسار العميلي).
