## 3. مصفوفة أنواع الحسابات (كما ثبتت من الكود: `user_role` enum + مسارات المصادقة)

| # | الدور | كيفية الحصول عليه للاختبار | الأسطح المختبرة |
|---|---|---|---|
| 1 | **Guest (زائر مجهول)** | بروفايل متصفح نظيف بلا جلسة | كل الصفحات العامة EN+AR · الأدوات الثمانية · المدونة · المكتبات · النماذج العامة |
| 2 | **Free Member (عميل مجاني)** | تسجيل بريد فوري جديد (بلا تأكيد بريد — قرار m9 القائم) | dashboard · plans · progress · questionnaires · referral · support · profile · checkout |
| 3 | **Premium/Pro/Coaching Member** | تفعيل من مدرب برصيد محفظة وهمي (المسار المعتمد — لا PayPal) | مزايا الباقات: مولدات AI الحية، حدود الـswaps، المخططات المحفوظة |
| 4 | **Coach B2B (مدرب)** | تسجيل ذاتي `/for-coaches/register` | coach dashboard · clients/invite · wallet · landing editor · ads · affiliate · support · help |
| 5 | **Coach B2C (site)** | تحويل النوع من الأدمن فقط (`PATCH /api/admin/coach-kind`) | صفحة الهبوط العامة للمدرب + الفروقات عن B2B |
| 6 | **Admin (أدمن)** | حساب أدمن اختباري موجود أو يُنشأ بوسيلة قاعدة البيانات المعتمدة | كل صفحات `/admin/*` + إجراءاتها الآمنة (شحن محفظة وهمية، مراجعة صفحات، إشعارات) |

**قاعدة الحسابات:** استخدام الحسابات الاختبارية الموجودة إن وُجدت (يُفحص `profiles` أولًا)، وإلا إنشاء حسابات جديدة بتسمية موحدة: `qa.ux0921.<role>.<n>@alkemos-test.com` — ولا حذف لأي حساب حقيقي إطلاقًا.

## 4. نطاق الاختبار التفصيلي (أمواج التنفيذ)

### الموجة A — الزائر (Guest) EN+AR
1. الصفحة الرئيسية + كل صفحات الأدوات الثمانية (BMI · سعرات · ماكرو · نسبة دهون · ماء · مخطط وجبات · مخطط تمرين AI · مخطط وجبات AI) — إنتاج نتيجة فعلية لكل أداة + حفظ نتيجة كزائر.
2. المكتبات: exercises · foods · programs · muscles · equipment · collections · compare · diet-plan — تصفح + فلاتر + صفحة تفصيل.
3. المدونة: قائمة + مقال + تصنيف + مؤلف. صفحات الثقة: about · contact (إرسال نموذج) · FAQ · memberships · for-coaches · affiliate · evo · coaching.
4. النماذج العامة: newsletter · lead capture · contact — التحقق من صحة المدخلات + رسائل النجاح/الخطأ بغتين.
5. i18n: التنقل EN↔AR، اتجاه RTL، مرايا الروابط، لا نصوص خام بلغة خاطئة.
6. الموبايل ‏390×844: الفوتر/الأهداف اللمسية (m1) · درج EVO (m2) · تجاوزات العرض.
7. Console نظيف بلا أخطاء hydration (H1) على عينة ≥10 صفحات لزائر نظيف.

### الموجة B — التسجيل والدخول (كل الأدوار)
1. تسجيل عميل جديد فوري → وصول /dashboard (مسار m9).
2. تسجيل ببريد موجود → رسالة «مسجل بالفعل» الصادقة بغتين (M2).
3. مؤشر قوة كلمة المرور في التسجيل فقط (m8).
4. دخول بكلمة مرور خاطئة → رسالة معربة داخل AR ومعربة الإنجليزية داخل EN (M1).
5. Google OAuth: التحقق من وجود الزر وسلامة المسار حتى تحويل Google (الإكمال بيد المالك — حد المنهج الموثق سابقًا).
6. استمرارية الجلسة: تحديث + خروج + حماية المسارات (`/dashboard` بعد الخروج → `/auth`).

### الموجة C — العضو المجاني (Free Member)
1. الاستبيانات: ملء كامل E2E + مراجعة الإجابات بتسميات مفهومة لا رموز خام (m5).
2. dashboard: البطاقات + رصيد الأدوات الصحيح = 8 (m4).
3. plans: توليد خطة AI (ضمن الحصص) + عرض «ميزة بريميوم» لبدائل الـFree (m6) + حفظ/تعديل.
4. progress: تسجيل وزن/صور + الرسم البياني + تذكير.
5. referral: صفحة الإحالات + نسخ الرابط.
6. support: فتح تذكرة E2E + ظهورها بالقائمة.
7. profile: تعديل البيانات + رفع صورة (avatars bucket).
8. EVO chat: محادثة فعلية + **مسح المحادثة من الجهاز بعد الخروج (m3)**.
9. checkout: الدخول لصفحة العضويات → اختيار باقة → صفحة الدفع — **إيقاف قبل أي بوابة دفع حقيقية** (الطريق الحقيقي للاختبار: طلب الدفع اليدوي إن وُجد أو رصيد وهمي — انظر الموجة E).

### الموجة D — المدرب B2B
1. تسجيل مدرب جديد ذاتيًا → /coach فورًا (slug خاص).
2. coach dashboard: بطاقات العملاء + دعوة عميل (invite E2E ببريد اختباري).
3. محفظة المدرب: رصيد $0 → محاولة تفعيل coaching لعميل → 402 برسالة i18n صحيحة (M1-أ) — **لا شحن حقيقي**.
4. landing editor: تعديل صفحة الهبوط + حفظ + preview (pending review).
5. ads · affiliate · support · help — فتح كل صفحة وإتمام إجراء واحد حقيقي على الأقل حيثما أمكن بأمان.
6. جرس الإشعارات: **صفر إشعارات موجهة لغير هذا المدرب (إعادة تحقق C1)**.
7. CoachSlugClaimer: المطالبة بـslug إن ظهر التدفق.

### الموجة E — الرصيد الوهمي (Virtual Balance E2E — بديل الدفع الحقيقي المُلغى)
1. الأدمن يشحن محفظة المدرب الاختباري برصيد وهمي من `/admin/wallets` (المسار المعتمد نفسه من المرحلة 228 — سجل created_by=الأدمن).
2. المدرب يفعّل اشتراك coaching لعميل اختباري من محفظته → خصم الرصيد + سجل دفع + إشعار.
3. العميل يصبح Premium فعلًا → فتح مولدات AI الحية (وجبة + تمرين) وإنتاج خطط حقيقية + حدود الـswaps المتغيرة.
4. طلب شحن محفظة من المدرب (`/api/coach/wallet/topup` بحالة request) + ظهوره للأدمن.
5. **PayPal وكل بوابات الدفع الحقيقية: خارج النطاق نهائيًا بأمر المالك — يوثق كملغى الاختبار.**

### الموجة F — الأدمن
1. دخول بأدمن اختباري → كل صفحات `/admin/*` ترندر بلا أخطاء: dashboard · members · clients · coaches · coach-system · coach-pages · coach-support · assignments · site-assignments · wallets · payments · finances · referrals · leads · saved-results · evo-analytics · external-plans · accounts · blog.
2. إجراءات آمنة فعلية: شحن محفظة (E) · تعليم حساب اختباري · مراجعة/اعتماد صفحة مدرب اختباري · إشعار broadcast لأدوار محددة.
3. بوابات الحماية: كل مسارات API الإدارية ترد 401/403 لغير الأدمن (عيّنة من كل عائلة).
4. تحويل مدرب B2B→site (B2C) ثم فحص صفحة هبوطه العامة.

### الموجة G — إعادة تحقق إصلاحات 2026-09-18 (Regression)
جدول تحقق سريع لكل بند أُغلق سابقًا: C1 (الإشعارات) · H1 (hydration) · M1 (i18n الأخطاء) · M2 (البريد المكرر) · m1..m9 — بند ينكسر = يمسك كمشكلة جديدة بجذر «انحدار».

### الموجة H — مدونة AI والتغييرات الأخيرة (230–242)
1. صفحات الأطعمة المعربة الجديدة (عيّنة من نطاق 2,409) تُخدم nameAr صحيحًا + `/api/food-search?lang=ar` يعمل.
2. مدونة: مقال حديث يعرض سليمًا (عربي خالص بلا خلط لاتيني خارج الأقواس) + category + RSS + sitemap تفتح.
3. أداء إدراكي: زمن استجابة الصفحات الرئيسية معقول (مراقبة بصرية، بلا قياس CWV رسمي — خارج النطاق).

## 5. القيود والقوانين الملزمة

1. **ممنوع نهائيًا:** أي معاملة دفع حقيقية (PayPal أو غيره) — كل المسارات المالية برصيد وهمي فقط.
2. **ممنوع:** تعديل أي كود/ميجريشن/إعداد Vercel أو Supabase أو Cloudflare — الاختبار قراءة + إجراءات UI آمنة فقط.
3. **ممنوع:** حذف أو تعديل بيانات مستخدمين حقيقيين — كل الإجراءات التخريبية على حسابات `qa.ux0921.*` حصرًا.
4. **ممنوع:** كتابة أي سر (توكن/كلمة مرور) في أي ملف — الحسابات الاختبارية بكلمات مرور مولدة تُذكر داخل المحادثة فقط.
5. لا دشّ قاعدة بيانات: أي كتابة SQL قراءة-فقط للتحقق، والكتابة عبر واجهات المنتج المعتمدة (UI/كاتب `coach_adjust_wallet` المعتمد).
6. التوثيق: تقرير `docs/UX-TEST-REPORT-2026-09-21.md` + صفاه في `docs/README.md` + مدخل worklog — كوميت docs-only يحمل `[vercel skip]` (قانون §10.5-2(أ)).
