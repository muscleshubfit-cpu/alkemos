## 1. الملخص التنفيذي

خضعت المنصة لتدقيق مستقل شامل: **2,160 رابطًا من الـ sitemaps زُحفت بالكامل (100% HTTP 200 — صفر 404، صفر تحويلات غير مقصودة)**، وأعيد تشغيل بوابات الجودة من استنساخ نظيف (**eslint 0/0 · vitest 1216/1216 · build ناجح** مع 4 أخطاء TypeScript مسبقة موثقة)، وقِيست الأداء فعليًا عبر متصفح headless على الرئيسيتين EN/AR، وفُحص السطح البرمجي كاملًا (76 مسار API + RLS + المصادقة)، ودُقّقت وثائق المشروع الثلاث (AGENTS/STATE/worklog) ضد الكود والإنتاج.

**الخلاصة العامة: المشروع في حالة تقنية وصحية ممتازة ظاهريًا — الصفحات تعمل كلها، الاختبارات خضراء، الأمان محكم، والـ SEO منظم بمعايير احترافية. لكن التدقيق المستقل كشف ثلاث فجوات جوهرية تحت السطح:**

1. **سياسة الكاش الموثقة (SEO-GEO-4) غير فعّالة في الإنتاج:** كل صفحات HTML الحية تُقدَّم بـ `Cache-Control: private, max-age=300, must-revalidate` — وليس السياسة المعلنة في `next.config.ts` (`public, max-age=0, must-revalidate, s-maxage=3600, stale-while-revalidate=86400`). كما أن `x-vercel-cache: MISS` على كل HTML (كل طلب = استدعاء دالة على Vercel)؛ الكاش الحقيقي الوحيد يعمل في **Cloudflare** (خارج سيطرة المستودع بالكامل). التعليقات داخل `src/middleware.ts` تدّعي أن «next.config.ts headers() يفوز» — وهو ما تحقق محليًا على `next start` لكنه **غير صحيح في الإنتاج**.
2. **تعفن حوكمة التوثيق تراكمي ومنهجي:** دورية تدقيق التوثيق الإلزامية (§12.5.2) متوقفة منذ 2026-08-25 (~130 مرحلة)، ونتيجتها المباشرة: قانون الاسم في AGENTS.md فُسد ذاتيًا بعد rebrand عام، وSECURITY.md يناقض AGENTS.md في قانون تطبيق الميجريشنز، وترتيب worklog مكسور في موضعين (مراحل 206–211 في أسفل الملف، و213 تحت 212)، و`archive/PROGRESS.md` عُدّل بعد تجميده الرسمي، وأغلب ترويسات «Last updated» في الوثائق الكبرى خاطئة بـ4–12 يومًا، وREADME يحمل رقمًا خاطئًا («6 أدوات مجانية» والصحيح 8).
3. **حمل JavaScript ثقيل على الرئيسية (~1MB من أصل 1.3MB أول تحميل عبر mobile)** + **CLS أعلى قليلًا من عتبة «الجيد» في اللغتين** (0.103 EN / 0.107 AR، العتبة 0.1) + صفحات equipment/muscles ضخمة (حتى 539KB HTML مضغوط و2,749 DOM node في `/equipment/bodyweight` بسبب تصيير 348 بطاقة تمرين بلا حد).

**توصية أمان فورية (خارج المستودع):** مفتاح GitHub (fine-grained PAT) الذي استُخدم لهذه الجلسة ظهر نصًّا في المحادثة — **يجب تدويره فور انتهاء هذه المهمة** (انظر المؤكد رقم 1 أدناه).

**لا توجد أي مشكلة من المستوى الحرج (P0)**: لا ثغرة قابلة للاستغلال، ولا صفحة مكسورة، ولا secret مكتوم في المستودع، ولا فجوة مصادقة/تصريح (فُحصت الـ76 مسار API واحدًا واحدًا — البوابات fail-closed في كل السطح الإداري والحساس).

## 5. المشاكل المؤكدة (مرتبة بالأولوية)

> «مؤكدة» = توجد أدلة مباشرة قابلة لإعادة الإنتاج (كود + قياس حي + مقارنة git). كل بند يحمل: الموقع الدقيق، الأثر، الأولوية.

### 🔴 الأولوية P1 (عالية — تعالج في الموجة الأولى من الخطة)

**المؤكد 1 — انكشاف مفتاح GitHub (PAT) في نص المحادثة** 🔐
- **الموقع:** خارج المستودع — بيانات الجلسة (الرسالة التي طلبت فيها التدقيق تحمل fine-grained PAT كاملًا).
- **الدليل:** المفتاح مرئي نصًّا صريحًا في المحادثة، واستُخدم فعليًا للاستنساخ وسيُستخدم للـ push.
- **الأثر:** أي طرف يطلع على هذه المحادثة يحصل على صلاحيات المفتاح على المستودع (حتى لو كانت صلاحياته محدودة بالـ repo).
- **المطلوب فورًا:** تدوير المفتاح (GitHub → Settings → Developer settings → Fine-grained tokens → revoke/regenerate) **بعد اكتمال الـ push لهذه المهمة مباشرة**. لا يوجد أي أثر للمفتاح داخل ملفات المستودع (تم مسحه بنمطيات متعددة — نظيف).

**المؤكد 2 — سياسة كاش HTML الموثقة غير مطبقة في الإنتاج (SEO-GEO-4 غير فعّال)**
- **الموقع:** `next.config.ts` (قاعدة `headers()` الأخيرة — الأسطر 238–245) مقابل السلوك الحي؛ والتعليق المعاكس في `src/middleware.ts` (الأسطر 32–56).
- **الدليل الحي (قياس مباشر):** كل صفحات HTML العامة (`/`، `/ar`، `/exercises`، مقالات المدونة…) تُقدَّم بـ:
  `cache-control: private, max-age=300, must-revalidate` + `x-vercel-cache: MISS`
  بينما الكود يعلن: `public, max-age=0, must-revalidate, s-maxage=3600, stale-while-revalidate=86400`.
  في المقابل: `sitemap-pages.xml` يُقدَّم بـ`public, max-age=3600, stale-while-revalidate=86400` + `x-vercel-cache: HIT` (ISR يعمل)، و`robots.txt` بـ`public, max-age=86400` (مطابق) — أي أن الخلل خاص بصفحات HTML الديناميكية تحديدًا: قراءة `headers()` في الـ root layout (لغرض `x-pathname` اللغوي) تجعل كل صفحة `ƒ Dynamic`، وفي هذه الحالة تتفوق قيمة إطار العمل/البنية على قاعدة `next.config.ts headers()`.
- **الأثر:** (أ) كل طلب HTML عند فوات كاش Cloudflare = استدعاء دالة على Vercel (كلفة + تذبذب TTFB — يتسق مع شكوى «speed variance» الموثقة تاريخيًا في المشروع)؛ (ب) سياسة `s-maxage=3600` الموثقة بتفصيل مدقق (SEO-GEO-4) لا تصل إلى أي CDN؛ (ج) الكاش الحقيقي الوحيد هو Cloudflare (قياس: `cf-cache-status: HIT` و`age: 1592+` على صفحات `private`!) — أي أن CF مضبوط بقاعدة «Cache Everything» تتجاهل `private`، وهذه الطبقة **غير موثقة في المستودع نهائيًا** ولا يعرف الكود شيئًا عن TTL الفعلي فيها؛ (د) تعليقات middleware.ts تدّعي آلية خاطئة عن الطبقة الفائزة في الإنتاج.
- **الأولوية:** P1 (أداء + كلفة + تضليل توثيقي للفريق المستقبلي).

**المؤكد 3 — إيقاف دورية تدقيق التوثيق الإلزامية (§12.5.2) — السبب الجذري لتعفن التوثيق**
- **الموقع:** `AGENTS.md` §12.5.2 (القانون) مقابل `worklog.md` (صفر مدخلات `DOC-AUDIT-*` حية منذ 2026-08-25).
- **الدليل:** القانون يوجب تدقيقًا شهريًا + بعد كل feature كبير (خلال 7 أيام) + بعد أي force-push (خلال 24 ساعة). منذ آخر تدقيق نفُّذت ~130 مرحلة (EVO-5، إطلاق وإلغاء EVO-6، إعادة هيكلة الرئيسية، أمواج SEO-GEO كاملة…) دون أي تدقيق توثيق واحد. كل المشاكل التوثيقية المؤكدة أدناه (4–24) كانت ستُكتشف لو اشتغلت الدورية.
- **الأثر:** الوثائق الحاكمة (التي يقرؤها كل وكيل جديد كأول خطوة — §3.6) تعلّم نموذجًا ذهنيًا خاطئًا عن المشروع؛ البوابات الحالية (docs_audit.py) تتحقق من **البنية** لا **الحقيقة** (تواريخ، ترتيب، تجميد، اتساق عبر الملفات).
- **الأولوية:** P1 (حوكمة).

**المؤكد 4 — تناقض قانون تطبيق الميجريشنز بين AGENTS.md وSECURITY.md**

- **الدليل:** نصان متعاكسان حرفيًا في الملفين؛ والواقع (الموثق في AGENTS.md وSTATE.md) هو التطبيق التلقائي منذ المرحلة 61.
