## 1. جرد حالة كاش المنطقة alkemos.com (تدقيق قراءة-only عبر API — 2026-09-30 UTC)

- **المنطقة:** `alkemos.com` · id `b4be55a0736831d9c5d9564788861076` · **الخطة: Free Website** — قيد حاكم لكل قرارات البند.
- **إعدادات المنطقة:** `cache_level=aggressive` · `browser_cache_ttl=0` (احترام الأصل) · `edge_cache_ttl=7200` (موروث بلا Page Rules — غير فاعل) · صفر Page Rules.
- **قاعدتا Cache Rules النافذتان (الحرف من `http_request_cache_settings`):**
  1. `alkemos-public-html-cache` — تطابق كل المسارات العامة (باستثناء `/api` و`/admin` و`/auth` و`/checkout` و`/dashboard` و`/questionnaires` و`/progress` و`/plans` و`/profile` و`/support` و`/referral` و`/preview` و`/coach` وكل ما يحوي `.`) → `cache: true` · **`edge_ttl: override_origin, default=43,200s` (12 ساعة)** · `browser_ttl: override_origin 300s`. تاريخها الموثق: 3,600s → 14,400s (T-3 · VERCEL-USAGE-3) → **43,200s (T-3b · VERCEL-USAGE-4 — حرس تجاوز Fluid CPU على خطة Vercel Hobby)**.
  2. `alkemos og-image cache` (T-1 · VERCEL-USAGE-3): `/api/og-image/*` → `cache: true` · `edge_ttl: override_origin 86,400s` — مثبتة حيًا اليوم: MISS→HIT بـ`cache-control: max-age=86400`.
- **قاعدة WAFcrawler-allow** (SOCIAL-OG-2): سماح زواحف المشاركة (facebookexternalhit/Twitterbot/WhatsApp/LinkedInBot/TelegramBot/Slackbot/Discordbot) — خارج نطاق البند ولم تُمس.
- **الأصل (Vercel):** يرسل للـHTML المخدوم `cache-control: public, max-age=300, must-revalidate, s-maxage=3600, stale-while-revalidate=86400` + `x-vercel-cache: PRERENDER` — والمقيس حيًا: حافة CF تتجاوز s-maxage للأصل بسنوات القاعدة (HIT بعمر 5,081s > 3,600s) — أي أن «نافذة الانتقال» الموثقة بSOCIAL-OG-3 §5.1 ناتج قاعدة الحافة المقصودة، لا خللًا.

## 2. القرار 1 — Cache Reserve: محجوب بخطة المنطقة (لم يُنفّذ — قرار كلفة للمالك)

- **مصفوفة التوفر الرسمية** (وثائق Cloudflare، آخر تحديث 2026-09-29): Cache Reserve **يتطلب خطة مدفوعة** («While Cache Reserve does require a paid plan…») — منتج استخدام-مدفوع على تخزين R2، والمصفوفة: Tiered Cache وSmart Topology متاحان على **Free**، بينما Regional/Custom/Generic Topology = **Enterprise حصرًا**.
- **مجسّات API على هذه المنطقة (أدلة خام):** مسار `cache_reserve` غير معروض للمنطقة (No route) · الإعداد غير معرّف — متسق مع قيد الخطة. نفس القيد مثبت على Regional Tiered Cache بالخطأ الصريح `1135: «this zone setting is not available for your plan type»`.
- **ما كان سيعطيه:** تخزين كائنات الكاش في R2 ليعيش الإخلاء والكولوهات الباردة — يخاطب بالضبط وجع «MISS الأولى» (175/178) عبر النشرات والمناطق.
- **مسار التمكين:** ترقية المنطقة إلى Pro (كلفة شهرية) + تفعيل Cache Reserve من لوحة المالك (يكشف مساره حينها) — **قرار مالك حصرًا، لم يُلمس**.

## 3. القرار 2 — تفعيل Tiered Cache (المفتاح الرئيسي): منفّذ اليوم ✓ — التغيير الجوهري للبند

- **الحالة قبل (مقيسة):** `GET /zones/{id}/argo/tiered_caching` → `{"value": "off"}` — رغم أن **Smart Topology = `on` منذ 2026-09-06** (إنشاء المنطقة): المفتاح الرئيسي مطفأ ⇒ الطبقات الهرمية لم تكن تعمل إطلاقًا، وإعداد Topology بلا أثر.
- **التنفيذ (النداء الرسمي الموثق بوثائق CF «Enable Tiered Cache via API»):** `PATCH /zones/b4be55a0736831d9c5d9564788861076/argo/tiered_caching` بجسم `{"value":"on"}` → **HTTP 200 success، والقيمة المرجعة `on` بطابع `2026-09-30T18:25:54Z`** (التوكن يحمل Zone Settings Write). أُكّد Smart Topology بقيمة مرجعة `on` (PATCH موثق، بلا تغيير — `modified_on` كما هو).
- **لماذا هو العلاج المتاح للوصفة:** عند MISS في كولو الزائر، يُسأل الطبقة العليا (Smart Topology تختار الأقرب للأصل بقياسات زمن الوصول) قبل الأصل — **فقط الطبقة العليا تملأ من الأصل** ⇒ تقليل تكرار «الرحلة الكاملة» عبر الكولوهات (زوار MENA/أوروبا/آسيا/أمريكا على مناطق مختلفة) وتقليل حمل الأصل على Vercel Hobby — نفس هدف Cache Reserve لكن مجانًا على الخطة الحالية.
- **التراجع:** نداء واحد `PATCH` بقيمة `"off"` (موثق هنا) — لا مساس بأي قاعدة كاش أو WAF أو TTL.
- **التحقق بعده:** `GET` يرجع `on` · خدمة حية سليمة على `/` و`/ar` (200 HIT — لا انحدار). **حد صادق:** أثر نسبة HIT التراكمي يُقاس من لوحة CF ▸ Caching ▸ Analytics (صلاحية Analytics ليست على التوكنات الحالية) — نافذة مالك للرصد، والرقم الرسمي «بعد» لن يتغير بزيارة واحدة.

## 4. القرار 3 — مراجعة TTL الحافة: الحكم «إبقاء 43,200s» (مراجعة فعلية، لا تغيير تطبيقي)

| الخيار | الحكم | الدليل |
|---|---|---|
| خفض (عودة نحو 3,600/14,400) | **مرفوض** | القيمة الحالية قرار موثق بعمد (T-3b · VERCEL-USAGE-4) كحرس تجاوز **Fluid CPU** على خطة Hobby — خفضها يستدعي عودة مخاطر الكلفة/التقييد الموثقة، ويزيد تكرار MISS الحاجب (عكس هدف البند) |
| رفع (نحو 86,400+) | **مرفوض** | يضاعف ألم نافذة انتقال HTML الموثقة (SOCIAL-OG-3 §5.1: التحديثات بطاقات المشاركة تنتظر انقلاب الحافة) مقابل وفر CPU هامشي |
| **إبقاء 43,200s** | **المعتمد** | يعمل كما صُمم (HIT بعمر 5,081s حيًا)، يوازن ندرة الأصل مع نضارة ≤12h، **ويعمل الآن مع Tiered Cache المفعّل**: إعادة الملء عند انتهاء TTL تتم عبر الطبقة العليا المشتركة بدل اندفاع كل كولو إلى الأصل — هذا بالضبط «رفع الفعالية» بلا لمس TTL |
| القطع الثابتة | **كما هي — محكومة بالأصل** | `/_next/static/*` و`/images/exercises/*` سنة immutable · `/images/brand/*` `max-age=300, SWR=604800` (مقيسة حيًا MISS→HIT اليوم) · og-image يومًا — كلها محترمة ولا تحتاج مراجعة |

## 5. القرار 4 — منطقة Vercel ثانية: تقييم موثق، توصية «تأجيل» (قرار كلفة للمالك)

- **المثبتات:** خطة الفريق **Hobby** (بيانات النشر الرسمية عبر Vercel API: `"plan": "hobby"` على نشر `1eeff863` الإنتاجي) · `regions: ["fra1"]` (`vercel.json:8`) · المنطقة مثبتة حيًا (`hkg1::fra1`) · دوال edge-runtime تعمل أصلًا قرب الزائر (مولّد og-image رُئي عبر `hkg1::sin1` — أقرب منطقة لحافة الطلب، سلوك منصة لا إعداد).
- **قيد المنصة:** Hobby = منطقة دوال واحدة؛ الثانية تتطلب ترقية Pro (كلفة شهرية) وتغيير `regions` — **قرار كلفة مالك، لم يُلمس**.
- **التحليل:** صفحات الموقع يخدمها كاش حافة CF أصلا (HTML 12h · statics سنة) — الزائر لا يدفع RTT الأصل إلا على MISS، وTiered Cache المفعّل اليوم يقلص هذه الحالات إلى الطبقة العليا؛ الدوال المثبتة fra1 (ISR/API) منخفضة الطلب حاليًا؛ الجمهور الأمريكي/الآسيوي يخدمه توزيع Vercel للـPRERENDER عند MISS (رُئي `hkg1::7j8p2`).
- **التوصية الموثقة:** تأجيل — يُعاد التقييم عند (نمو حركة API محسوسة · شكاوى زمن استجابة تفاعلية · ترقية أي من المنصتين لأسباب أخرى). إن فُتح لاحقًا: المرشح `iad1` (الجمهور الأمريكي الأثقل بعد MENA).
