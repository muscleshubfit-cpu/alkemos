## 1. الملخص التنفيذي

اختُبرت المنصة كاملة الأدوار: **Guest → Free → Premium (بالرصيد الوهمي) → Coach B2B → Coach B2C (site) → Admin** عبر 8 أمواج (A–H) في الخطة. النتيجة العامة: **المنصة في حالة صلبة بعد إصلاحات 2026-09-18** — كل بنود التدقيق السابق (C1 · H1 · M1 · M2 · m1–m9) أُعيد التحقق منها حيًا **وما زالت حية**، وكل المسارات الأساسية (تسجيل، أدوات، استبيانات، توليد AI، تقدم، دعم، محفظة، تفعيل، مراجعة صفحات، تحويل B2C، اعتماد دفع يدوي) تعمل E2E.

**الاكتشاف الجديد الأهم (H1-2026):** خلل مسار **«دعوة المدرب → تسجيل العميل المدعو»** — الدعوة تُنشئ حسابًا ظلًا بكلمة مرور فارغة في `auth.users` قبل تسجيل العميل، فيعلق العميل المدعو بين شاشة «Account already exists» وشاشة «Invalid login credentials» بلا مخرج إلا رابط الدعوة الإيميلي. موثق بالكامل مع إعادة إنتاج في §3.

**ثلاث مشاكل إضافية** (متوسطة/صغيرة) + **سبع فرص تحسين** — التفاصيل أدناه.

## 3. النتائج الجديدة (مرتبة بالخطورة)

### 🔴 H1-2026 — طريق مسدود في تسجيل العميل المدعو (دعوة المدرب → حساب ظل بكلمة مرور فارغة)

- **السلسلة الحية (موثقة بحسابين):**
  1. المدرب يدعو `qa.ux0921.client3@…` → `/api/coach/clients/invite` يستدعي GoTrue `inviteUserByEmail` الذي **يُنشئ صف `auth.users` فورًا بكلمة مرور فارغة** (تحقق SQL: `encrypted_password=''` وقت الدعوة، قبل أي تسجيل من العميل) + صف `coach_assignments`.
  2. العميل المدعو يفتح الموقع ويسجّل كأي زائر (بلا علمه برابط الإيميل) → GoTrue يرد **200 مضادًا للاستكشاف** (البريد موجود) → الواجهة تعرض «Account already exists — Sign in with your password to get straight back in» — لكن كلمة المرور التي اختارها العميل **لم تُخزَّن أصلًا** (تحقق SQL: الصف كما هو، لا جلسة، `last_sign_in_at` فارغ).
  3. العميل يتبع النصح ويسجل الدخول → «Invalid login credentials» — حقيقي وليس غلطته.
  4. **المخرج الوحيد:** رابط الدعوة الإيميلي (أول استخدام) — وارتباط موثوقية إيصال البريد (SMTP) يجعل تعطل المسار كليًا محتملًا.
- **تأثير إضافي:** المدرب يرى العميل المدعو في قائمة عملائه كأنه مسجل («No sub») — ما يضخّم عدّاداته ويطمئن زورًا.
- **الأثر:** أعلى نقطة تحويل في مسار B2B (عميل جديد مدعو) تعمل بلا مخرج ذاتي. فُقدان عملاء + تذاكر دعم.
- **الحلول المطلوبة (بالترتيب المفضل):**
  1. **تفعيل عند التسجيل:** عند signup ببريد صفّه invitee بكلمة مرور فارغة → أكمل التفعيل: اكتب كلمة المرور المختارة + فتح جلسة + حفظ الإسناد (يمسح الحاجة لرابط الإيميل ويحافظ على الإسناد).
  2. شاشة «Account already exists» تكتشف صف الـinvitee (كلمة مرور فارغة) فتعرض «أكمل تفعيل حسابك» (تعيين كلمة مرور) بدل «سجّل دخولك».
  3. جذرًا: أوقف `inviteUserByEmail` من إنشاء الحساب قبل أن يختار العميل كلمة مرور — اجعل الدعوة صف انتظار (pending_invites) لا صف auth.
- **إعادة الإنتاج:** مدرب يدعو بريدًا غير مسجل → سجّل بالبريد نفسه من شاشة التسجيل العامة → «Account already exists» → «Log in» بكلمة المرور المختارة → «Invalid login credentials».

### 🟡 M-2026 — خلط لغات في صفحة العميل عند المدرب (واجهة EN برسالة عربية خام)

- صفحة إدارة العميل `/coach/{clientId}` بواجهة إنجليزية تعرض في قسم Overview رسالة فارغة الحالة بالعربية الخام: «لا توجد بيانات كافية لعرض المؤشرات الصحية. ابدأ بإضافة قياسات للعميل.» — نفس جنس M1 المُصلح في مسارات أخرى (موقع جديد لم يغطه الإصلاح السابق: CoachClientView).
- **الحل المطلوب:** تمرير النص عبر كتالوج error-i18n/مفاتيح i18n كما نُفذ في M1 (المصدر: رسالة سيرفر داخل مكوّن العرض).

## 4. ما ثبتت سلامته (قائمة تحقق إيجابية مختصرة)

- **الزائر:** 23 صفحة EN + 10 مرايا AR بمحتوى كامل وRTL صحيح · حاسبة BMI E2E (نتيجة 26.8/Overweight/وزن مثالي/PDF/JSON/حفظ→/auth) · newsletter وcontact وlead بنماذج صالحة · 404 مخصصة سليمة (comparison/exercise بمسارات خاطئة) · تبديل اللغة يعكس الرابط (`/tools/bmi-calculator` ↔ `/ar/tools/bmi-calculator`).
- **العضو Free:** تسجيل فوري → dashboard · استبيان 3 خطوات E2E → مراجعة مفهومة → إرسال («Submitted») · توليد خطة AI حية (فطور/غداء/عشاء بالسعرات) تُحفظ تلقائيًا (Meal plans: 1) · حصة EVO المعروضة (0/2 خطط، 9 رسائل) · تسجيل check-in (84.5kg/89cm/طاقة 7) يظهر بالرسم والسجل · تذكرة دعم E2E · إحالات (20%/$10) · EVO يجيب ويعرض الحصص.
- **مسار المال بالرصيد الوهمي (بدون PayPal إطلاقًا):** طلب شحن إيصال (30$ InstaPay + إيصال مرفوع) → طابور «Pending» → موافقة الأدمن → «Wallet credited» → رصيد 24$ بعد خصم 6$ بتفعيل اشتراك Coaching لعميل (سجلان في الـledger بملاحظات صحيحة) → العميل يرى «كوتشينج · 30 يوم · مفعّلة بواسطة مدربك · كاش · 6$» → حصص الـswaps تتحول إلى 6/6. **حصريًا عبر واجهات المنتج المعتمدة** (كاتب `coach_adjust_wallet` بواجهة الأدمن).
- **Checkout (بلا بوابة):** صفحة الدفع تعرض الخطة/المدة/الإجمالي وسياسة 7 أيام؛ المسار اليدوي (InstaPay/فودافون + إيصال) أرسل طلبًا حقيقيًا → ظهر في طابور الأدمن → «Subscription approved and activated!». زر PayPal حاضر بالواجهة ولم يُضغط (خارج النطاق بأمر المالك).
- **المدرب:** تسجيل ذاتي → landing editor → Publish → «Pending admin review» → اعتماد الأدمن («Approved — page is now public») → الصفحة العامة حية بالتخصصات والنبذة · دعوة عميل (200 + إسناد) · جرس إشعارات نظيف · صفحات ads/affiliate/help تفتح.
- **الأدمن:** 17 صفحة إدارية ترندر بلا أخطاء · طوابير المال/الصفحات تعمل E2E · دفتر 35 حسابًا يعرض «4 Test accounts» · التحويل B2C: «Make site coach» → «Converted to a site coach» → قائمة site-assignments تستقبله → نص لوحة المدرب يتبدل لنص B2C.
- **الأداء الإدراكي:** كل التنقلات استجابت في حدود معقولة على الاتصال الاختباري؛ لا مؤشرات بطء شاذ (القياس الرسمي خارج نطاق هذه الجولة).

## 5. فرص التحسين (غير عيوب)

1. **قائمة دعوات معلقة للمدرب** (يتكامل مع إصلاح H1-2026): حالة الدعوة sent/joined + زر إعادة إرسال — يقفل فجوة الرؤية الكاملة لمسار B2B.
2. **شاشة «Account already exists»**: عند وجود كلمة مرور فعلًا، أضف رابط «Forgot password?» مباشرة فيها لتقصير استرجاع الحساب.
3. **ملخص ما بعد الدفع اليدوي:** صفحة نجاح طلب الاشتراك تعرض الخطوات المتوقعة وزمن المراجعة التقريبي (يقلّل تذاكر «متى يتفعل؟»).
4. **تسمية الخطط المولدة:** التوليد التلقائي يحفظ الخطة فورًا (سلوك ممتاز) — اقتراح: إدخال اسم مقترح قابل للتحرير لحظة الحفظ لتحسين إدارة الخطط المتعددة.
5. **عرض حصة EVO داخل الدرج** (حاليًا في اللوحة) لتعزيز الإحساس بالقيمة في لحظة الاستخدام.
6. **slug من الاسم:** افتراض اسمي للمدرب عند التسجيل مع بقاء التحرير (تجميل تسويقي).
7. **توحيد عرض «Submitted» للاستبيانات** مع عرض القيم (يغني عن m-B جذريًا).
